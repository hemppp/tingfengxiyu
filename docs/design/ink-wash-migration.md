# 水墨化改造留档（2026-09-15）

> 把全站 UI 从「青霭玻璃」（冷调瓷白 + 霁青 #2383c7）完整迁移到**黑白水墨**。
> 主色**严格限定黑 / 白 / 灰度**（CSS 里饱和度恒为 0），运用浓淡墨色层次、笔触飞白与渲染晕染；
> 返回按钮改为毛笔手绘图标并配水墨交互反馈。

---

## 一、设计系统：墨分五色

传统水墨讲「墨分五色」——**焦、浓、重、淡、清**。改造把这五档映射为明度阶梯，
所有功能性区分**由色相改为明度**：

| 墨阶 | 明度 | 用途 |
|---|---|---|
| 焦墨 | 8–9% | 主文字、写作官、被挡下状态 |
| 浓墨 | 12–20% | 主色 `--primary`、角色、主强调 |
| 重墨 | 26–36% | 地点、物品、警示 |
| 淡墨 | 42–52% | 次要文字、伏笔、事件 |
| 清墨 | 58–72% | 待开始状态、大纲、占位 |

### 基础 token 映射（亮色 / `:root`）

| token | 原值（青霭玻璃） | 现值（水墨） |
|---|---|---|
| `--background` | `220 27% 96%` 冷调瓷白 | `0 0% 96%` 宣纸白 |
| `--foreground` | `224 28% 12%` 靛墨 | `0 0% 9%` 焦墨 |
| `--primary` | `205 70% 46%` 霁青 | `0 0% 12%` 浓墨 |
| `--border` | `220 16% 88%` | `0 0% 82%` |
| `--muted-foreground` | `221 10% 46%` | `0 0% 42%` 淡墨 |
| `--destructive` | `0 72% 51%` 红 | `0 0% 16%` 最重墨 |
| `--glass-blur` | `24px` | `10px`（纸不折射） |
| `--glass-saturate` | `180%` | `100%`（去饱和提升） |

> ⚠️ **`--destructive` 的危险语义靠"最重墨 + 描边"表达**，不再靠红色。
> 若某处确实需要彩色警示，把该值换成 `0 72% 45%` 即可局部恢复（注释已留在 `globals.css`）。
> **暗色模式必须单独覆盖 `--destructive`**（亮色值是 16% 深墨，在夜底上完全不可见）。

### 语义扩展层（15 色 → 墨阶）

原**彩色区分**的语义色全部改墨阶，靠深浅区分而非色相：

| 组 | 原 | 现 |
|---|---|---|
| 实体（6） | 深青 / 柳绿 / 远山青 / 赭石 / 雾靛 / 冰青 | 焦 12% → 清 68% 六档 |
| 智能体（5） | 青 / 深青 / 赭 / 柳绿 / 绿 | 20% / 30% / 40% / 50% / 8%（写作官最重） |
| 状态（4） | 灰 / 赭 / 绿 / 红 | 待开始 72% / 进行中 40% / 已完成 14% / 被挡下 8% |

### 主题

| id | 名称 | 说明 |
|---|---|---|
| `ink` | **水墨** | 默认。宣纸白底 + 浓淡墨，大圆角（16/20/24px） |
| `soot` | **松烟** | 暗色锁定。松烟墨底 + 亮墨，硬边小圆角（4/6/8px） |

> 原 `azure` / `arcade` 的 id 一并改名。老用户 localStorage 里的旧值会在
> `readStored()` 里找不到而**回落到默认（水墨）**，即自动迁移，无需迁移代码。

## 二、核心手法：改 token 层，不逐个改组件

项目此前已铺好「换肤契约」（`globals.css` 的语义扩展层注释 + `tailwind.config.js` 里
语义色引用 CSS 变量），所以**绝大部分界面改一处即生效**。真正要另改的只有两类：
**① Tailwind 内置彩色调色板；② 组件里的硬编码色值 / RGB 元组。**

### ① Tailwind 内置色板重映射（`tailwind.config.js`）

组件里散落大量 `text-amber-500` / `bg-green-100` / `text-red-500`，
逐处改既慢又必漏。改为在配置层**一次性把 17 个内置彩色调色板整体映射到灰阶**：

```js
const INK_STEPS = { 50: 97, 100: 94, 200: 88, 300: 80, 400: 66,
                    500: 52, 600: 42, 700: 32, 800: 24, 900: 15, 950: 10 };
const INK_SCALE = /* 每档 → `hsl(0 0% L%)` */;
const CHROMATIC_PALETTES = ['red','orange','amber','yellow','lime','green','emerald',
  'teal','cyan','sky','blue','indigo','violet','purple','fuchsia','pink','rose'];
// colors: { ...INK_PALETTE, /* 其余语义色照旧 */ }
```

`500` 档取 52% 灰，**明暗两种模式下对比都够**，因此同一个值无需按模式分叉。

## 三、毛笔返回按钮（`components/ui/InkBackButton.tsx`）

### 图标：手绘笔触，非几何箭头

手绘 SVG（viewBox 24×24），由六笔构成，模拟毛笔的**提按**：

| 笔画 | 作用 |
|---|---|
| 主痕（1.85px 弧线） | 笔身，带自然波折而非直线 |
| 副痕（1.05px，62% 不透明） | 叠在主痕下方，形成粗细变化 |
| 起笔顿点（2.65px） | 左端最重的一按 |
| 上挑锋（1.7px） | 箭头的一撇 |
| 下挑锋（1.55px） | 另一撇，略短，收束更自然 |
| 飞白（0.85px 虚线，42% 不透明） | 笔身斜上方的断续细痕，模拟毫毛分叉 |
| 墨点（0.62r 圆） | 起笔处溅出一点，破掉机械感 |

### 交互：借自书法的三个动作（`.nm-ink-back`）

| 状态 | 效果 |
|---|---|
| **hover** | 墨迹**晕开** —— 径向渐变（`hsl(var(--ink)/0.14)` → 透明）配 `blur(3px)`，从 `scale(.35)` 扩到 `1`；笔身同时左移 1.5px（笔锋先探出） |
| **active** | 墨点**扩散** —— 一圈墨环 `scale(.72) → 1.65` 同时淡出（`nm-ink-ripple` 0.62s）；笔身下沉左移 3px 并缩到 0.94（落笔） |
| **focus-visible** | 墨环替代系统 outline：`0 0 0 2px background, 0 0 0 4px ring/0.5` |

全部动效尊重 `prefers-reduced-motion`。

### 覆盖的 4 处入口

| 页面 | 位置 |
|---|---|
| 管理后台 | `pages/AdminPage.tsx` |
| 设置页 | `pages/SettingsPage.tsx` |
| AI 写作工作台 | `components/layout/AutoWriteWorkbench.tsx` |
| 项目布局 | `components/layout/ProjectLayout.tsx` |

> 顺带修掉一处隐患：AdminPage 原返回按钮用 `hsl(var(--ink-soft))` —— **该变量全项目并未定义**，
> 属无效值。

## 六、⚠️ 踩坑记录

1. **hex 扫描会漏掉非 hex 的彩色**。本轮有两类漏网：
   - canvas 绘制用 **RGB 元组**（`BambooLeafFollow` 的竹叶是 `[25,80,25]` 这种绿）
   - CSS 里直接写 **`hsl(230 42% 78%)`**（`ambient-base` 的靛蓝薄纱）
   → **必须补两道扫描**：`hsl\([0-9]+ [1-9][0-9]*%` 和 RGB 三元组。只扫 hex 会得出"已全清"的**假结论**。

2. **灰阶下"减不同值"会产生色偏**。`BambooLeafFollow` 的描边原为 `-10/-10/-5`（在绿色上无害），
   改灰阶后必须**等量减**（`-12/-12/-12`），否则描边会偏色。

3. **暗色模式要单独覆盖 `--destructive`**。亮色值是 16% 深墨，夜底上完全不可见。

4. **颜色语义弱化是本次改造的固有代价**：危险操作失去红色提示，实体类型靠深浅区分
   （在色盲友好性上反而更好，但**辨识速度会慢于色相区分**）。若后续觉得不够，
   优先在**图标 / 形状 / 文案**上补区分，而不是把颜色加回来。

5. **`hsl(var(--x, #hex))` 是无效写法**：`ChapterEditor` 原有 `hsl(var(--error-bg, #fef2f2))` ——
   `hsl()` 里不能放 hex。已修正为灰阶三元组。

## 七、背景水墨作画层（2026-09-15 追加）

第一版背景只是「灰底 + 纸纹 + 两团淡墨晕」。作者要求**像毛笔画的画**，
`AmbientBackdrop` 遂重制为**一幅铺满视口的静态水墨横卷**（全局挂载于 `App.tsx`，`z-index:-1`）。

### 画面构成

| 元素 | 画法 | 墨色 |
|---|---|---|
| **远山三重** | 手绘 path，每条 4–5 个高低不一的峰 | 7% / 10% / 14%（近浓远淡） |
| **竹枝一丛**（左上） | 竿为细笔折线带节；叶是 `M0,0 C7,-11 19,-17 31,-15 C19,-6 8,2 0,0 Z` **一笔扫出的月牙面**（非描边） | 竿 0.34，叶 0.30 起递减 |
| **飞白扫笔** ×3 | 横向 `stroke` + `strokeDasharray` 断续 | 0.14 / 0.10 / 0.09 |
| **水岸线** ×2 | 远山脚下淡墨横线，起笔实、收笔虚 | 0.16 / 0.11 |
| **溅墨点** ×6 | 收笔甩出的点，破掉整齐感 | 0.11–0.20 |

### 两个技术要点

1. **`feTurbulence` + `feDisplacementMap` 做宣纸晕染** —— 把规则边缘打散成毛边。
   两个滤镜分工：`nm-ink-bleed`（低频，用于山与水岸）、`nm-ink-dry`（高频，用于竹与飞白）。
2. **墨韵渐变** `nm-ink-fade-x` / `-y`：一笔之内从 0 → 0.72 → 0 的浓淡过渡，
   模拟「蘸墨后一笔写到底」。

配色**全部**走 `hsl(var(--ink) / x)`，所以浅色（水墨）与暗色（夜墨）两套主题自动反相。

### ⚠️ 三条踩坑记录

1. **扁椭圆在宽屏上必然被读成「背景条纹」，而不是「云」**。第一版云气用了 4 个
   `rx=300 ry=30` 的椭圆，在 1440 宽上拉伸后就是三条横带，像污渍。
   **改成「水岸线」（有起收笔意的横线）后画面反而更透气** ——
   **水墨构图宁可留白，不要含糊的横带**。
2. **山形太平缓也会被读成「一条灰带」**。第一版远山是 3 段平缓弧线，三层叠加后
   就是一条横贯的灰色带。**必须手绘出 4–5 个明显峰谷**才读得出「山」。
3. **`feTurbulence` 是这份背景里最贵的一步** —— 它按 filter 区域逐像素计算。
   首版 `numOctaves=3/4` 时，同样一张 1440×900 截图**要跑 2.5 分钟、产物 888KB**；
   降到 `2/2` 后**降到 15 秒**，视觉几乎无差。**大面积滤镜务必压 octaves。**

### 性能与降级

- 整张画是**静态**的，只有两个动画：`ambient-ink-drift`（120s 极缓横向漂移）、
  `ambient-ink-bamboo`（14s、不到 1 度的摇曳）。两者都走 `translate3d` / `rotate`
  交合成器，不触发重排重绘。
- `prefers-reduced-motion: reduce` 下两个动画全关。
- 拖窗时（`body.nm-dragging-active`）暂停 —— 避免逐帧变化让玻璃面板的
  `backdrop-filter` 缓存失效、与拖拽合成抢 GPU。

## 八、背景压淡 + 按钮毛笔化（二次优化）

作者看 `/project` 空态页后反馈「山太实、叶子太多」，并要求「按钮 UI 改成毛笔的一点」。

### 8.1 背景：三个病灶与对应修法

| 症状 | 真因 | 修法 |
|---|---|---|
| 远山像「一块灰」 | **填充是纯色实心** —— path 底边那条水平直线让整座山读成实体块 | 改用 `nm-ink-fade-y` 渐变填充（山脊 0.9 → 山脚 0.04），**山脚自然隐入纸面** |
| 远山像「一片丘陵」 | 三条 path 的原始山脊都落在 y 200–340，**只做整体平移会叠在一起** | 给三条**不同纵向位移**（6 / 34 / 74），远山最高、近山最低，拉开纵深 |
| 山「压」着界面 | 山脊落在画面 22%–40% 高度 | 整体下移，天空留白增多 |
| 落叶喧宾夺主 | `count` 默认 **45** | 降到 **24**（`BambooLeafFollow`） |

> ⚠️ **调参基准**：空态页（`/project`、空书架）内容少，背景自然显得突出；
> **要拿有内容的页面做基准**，否则会为了迁就空态把背景压得过淡，在有内容的页面上就几乎没有笔意了。

### 8.2 按钮：为什么是「外勾一道墨线」而不是改形状

按钮的统一语言是 `border-radius: 980px` 胶囊（两端半圆）。把圆角换成多值「手绘圆角」会
**直接把胶囊变成方圆形块** —— 形态破坏过大。而毛笔味的本质是**笔锋**而非形状，
所以改为在按钮外再勾一道**微倾 0.5° 的墨线**，像写完一个字又用笔尖轻描了一遍：

| 状态 | 墨线行为 |
|---|---|
| 常态 | `inset: -2.5px`，`hsl(var(--ink) / 0.2)`，`rotate(-0.5deg)`，opacity 0.8 |
| hover | 扩到 `-3.6px`、加深到 0.32 —— **笔尖再描一遍** |
| active | 收到 `-1.4px`、opacity 1 —— **落笔收紧** |
| disabled | 不显示 |

覆盖 `.nm-btn-apple` 全系（`primary` / `secondary` / `ghost` / `destructive`），
`position: relative` 一并补上。
**成本**：纯 CSS 伪元素（1px 边框 + 0.5° 旋转），**零滤镜、零重绘** ——
与背景那套 `feTurbulence` 完全不是同一量级，再多按钮也不会拖慢。
