# 多智能体分层记忆架构 · 隔离与受控全局访问

> 目标：**两级分层 + 同层双式隔离 + 受控全局访问**，且整体上**不可能发生记忆污染**。
> 本文是规格（可直接施工）。落笔 2026-09-13。与既有设计的关系见 §11
> （《`docs/ai-writing-architecture.md` §6 灌溉水车》是本文 L1-叙事式里的一个环，不是另一套东西）。

---

## 0. 先把术语钉死（否则后面全是歧义）

| 词 | 本文含义 | 代码里的对应 |
|---|---|---|
| **agent（编排层）** | 多智能体系统这一层：负责装配上下文、闸门放行、沉淀落库、水车转动 | `orchestrator` / `context-resolver` / `entity-sink` |
| **智能体（agent instance）** | 单个角色实例，有自己的 system 与私有记忆 | `roles.ts` 的 `plot-designer` / `character-designer` / `continuity-keeper` / `convener` / `writer` / `reviewer` |
| **L1 全局记忆** | 一个项目一份、跨章跨智能体共享的**权威**记忆 | 现：`resolveSettingsDigest()` 装配的设定档 + `entity-sink` 落的库 |
| **L2 专属记忆** | 每个智能体**独立一份**的私有记忆 | 现：**尚无**（水车记忆未实现；当前靠"每轮现拼上下文"） |

**关于「双式记忆」的解读**（如与你的本意不同请指出，改一层定义即可）：
本文按下述第二种理解落地 —— **同一层内部两种形态**，两者必须物理+类型双重隔离：

- **事实式（Fact）**：短、可枚举、可校验、带来源指针 —— 能进"判断依据"的只有它
- **叙事式（Narrative）**：长、原文/摘要、天然不可校验 —— 只能被**引用**（必须带章号或发言 id），不能当事实

> 另一种可能的本意是"公有/私有双式"。那个语义已被 L1/L2 覆盖，无需再加一层维度。

## 1. 分层总览

### 1.0 先把「记忆方式」与「记忆迭代方式」分开（2026-09-13 澄清）

作者口径：**水车是记忆的迭代方式，不是一层共享记忆；记忆方式仍是各智能体独立的记忆。**

| 概念 | 是什么 | 不是什么 |
|---|---|---|
| **记忆方式（存储与归属）** | **每个智能体各自独立的记忆**（一 agent 一份，互不可读） | ❌ 不是"大家共用一块水车" |
| **记忆迭代方式（演进机制）** | **水车** —— 固定斗数 + 循环复用 + 出界压梗概，用来让记忆**滚动更新**而不无限增长 | ❌ 不是存储层、不是全局共享 |
| **全局记忆** | 只有**权威事实**（设定库）：世界观 / 实体 / 伏笔 / 约束 / 章节摘要 | ❌ 不含"谁的记忆"，也不含"上一章全文"这种素材 |

★ 直接后果：**水车在每个智能体内部各转各的** —— 它读到的前情进**它自己的水车**，
出界时压成的是**它自己的**梗概；两个角色的水车互不可见、互不影响。

```
L1 全局记忆 GlobalStore（一项目一份，**只有事实**）
   └─ 事实式 FactStore：世界观硬设定 · 实体表 · 伏笔台账 · 硬约束 · 章节摘要
                        写入：**只有** ingest()（沉淀器）   读取：需闸门授权（具名 reason）
        （叙述性素材如"上一章全文"不属 L1 —— 它是**被读取的项目数据**，
          读到时进入**读者自己的**水车；见 §1.1）

L2 专属记忆 AgentStore[agentId]（一智能体一份 · 互不可读）
   ├─ 事实引用：该智能体确认过的事实的**指针**（factId + 来源章节，不存副本）
   ├─ 经历流  ：它说过的话、它收到的同伴发言（它自己的视角）
   └─ **水车（迭代器）**：该智能体自己的工作记忆 —— 固定斗数、循环复用
          舀入：它经历/读到的新内容（定稿交付、被注入的前情）
          出界：最老一斗压成**一句话**，沉进**它自己的**长期池（原文不在这里）
```

### 1.1 水车怎么转（每个智能体各自独立地转）

```
        该智能体自己的水车（斗数固定，默认 1）
   [ 斗1 ch4 ][ 斗2 ch3 ][ 斗3 ch2 ]   → 出界（最老一斗）
        ↑ 每来一章，整体右移一格              ↓
        │                              压成一句话 → 它自己的长期池
        └── 舀入：定稿交付 / 它读到的前情
```
- **斗位序号本身就是相对时间戳**：斗 1 永远最新、斗 3 永远最老（引用时天然带新鲜度）。
- 三层时间戳：`chapterNo`（逻辑）/ `ingestedAt`（真实）/ `storyTime`（故事内）。
- **容量是每个 agent 的配置**，`WHEEL_CAPACITY_DEFAULT`：**2026-09-13 作者拍板 1 → 3**。
  代价是**每个角色每轮多带约 2 章全文**，因此配套必须有**注入篇幅上限**（见下）。
- **注入用"水车"而不是"统一上一章"**（扩容量时同步改的）：
  否则容量 3 只是个永不生效的数字。现在每个角色拿到的是
  `【最近章节（你自己的水车 · 斗 1 最新 · 最多 3 斗）】`。
- ⚠️ **篇幅上限 `WHEEL_MAX_CHARS = 12000`（必须有，不是可选项）**：
  三章都顶格（每章上限 6000 字）时一次注入可达 18000 字，乘上每轮多角色会吃掉大块上下文。
  策略：**斗 1 保证完整**（否则"没有前情"是假信息），之后从新到旧加，加不下就停并**明确标注
  「更早的 N 个斗位因篇幅省略；需要细节请按需回读」** —— 省略要让模型知道，而不是让它以为没有。
- ★ 关键差异：**不是"全项目一台水车、大家看同一份"**，而是**每人一台、各转各的**。
  同一个前情被两个角色读到，就分别进入两个人各自的水车，之后各自循环、各自压梗概。

**层级关系**（你的要求 4）：`可读范围(agent 层) ⊇ 可读范围(任一智能体)` —— 父级覆盖子级，
且父级能读 L1 的全部经授权键；子级**只能**读自己的 L2 + L1 的白名单键。

## 2. 各层职责（放什么 / 不放什么）

| 层 | 放什么 | **明确不放** | 生命周期 | 体量 |
|---|---|---|---|---|
| **L1-F 事实式** | 世界观硬设定、已确立的地理/规则、实体（角色/地点/物品）、伏笔状态（`planted/hinted/payed_off/abandoned`）、硬约束、已交付章节的一句话摘要 | 某角色的**猜测/转述/待定项**、草稿里的句子、讨论中的中间结论 | 长期，只增不删（可标废弃） | 小，可全量装配 |
| ~~L1-N 叙事式~~ | **已取消** —— 叙述性内容不在共享层（见 §1.0）。章节正文属于"项目数据"，按需读取（`recall-by-need`） | —— | —— | —— |
| **L2-F 事实引用** | 该智能体查过并采信的事实**指针**（`factId` + 它当时为什么采信） | 事实**副本**（副本会与全局失同步 → 变成第二真相） | 与本批次同生命周期 | 很小 |
| **L2-N 经历流** | 该智能体自己的发言、它收到的同伴发言（**按它的视角**，它没听到的就不在里面） | **其他智能体的私有记忆**、全局未授权的键、被交付前的草稿全文 | 批次结束归档 | 中，可压缩 |
| **L2-W 水车（迭代器）** | 该智能体自己的工作记忆斗位（它经历/读到的最近 N 章） | 别人的斗位；写作中的半成品（**不许占斗位**，否则自己的记忆被草稿污染） | 循环覆盖，出界压梗概沉入它自己的长期池 | 固定斗数，恒定体量 |

★ 两条最容易搞反的：
1. **L2-F 存指针不存副本** —— 否则全局记忆更新后，L2 里还是旧值，两个"事实"打架。
2. **L2-N 是视角而不是剧情** —— 这正是你要的"信息隔离"：剧情设计师不知道角色设计师的私有笔记，
   也**不该**知道剧情大纲以外的全貌（除非经授权读 L1）。

## 3. 隔离机制：三层防线

### 防线① 键空间隔离（物理层）

```
L1:  global/{projectId}/fact/{kind}/{key}         例 global/p1/fact/char/陈默
     global/{projectId}/narrative/chapter/{chapterNo}
L2:  agent/{projectId}/{agentId}/fact-ref/{factId}
     agent/{projectId}/{agentId}/experience/{turnId}
```
- 任何 L2 键都**内含 agentId**：拿不到别人的前缀，就构造不出别人的键。
- 落库时（现为 SQLite 多库）L2 用**独立表**：`agent_memory(agent_id, kind, key, value, ...)`，
  `agent_id` 是**必填列**且所有查询强制带它（`WHERE agent_id = ?` 由句柄生成，不接受调用方拼）。

### 防线② 接口隔离（类型层：让越权代码**编不过**）

```ts
/** 传给智能体的句柄：**只能**读写自己的 L2，读 L1 必须走 query() */
export interface AgentMemoryHandle {
  readonly agentId: string;                          // 只读，外部改不了
  readOwn(key: string): Promise<MemoryItem | null>;
  writeOwn(item: MemoryItem): Promise<void>;
  /** 读全局：必须带用途与键，闸门会校验白名单 */
  queryL1(q: { keys: string[]; reason: L1ReadReason }): Promise<MemoryItem[]>;
}
export type L1ReadReason =
  | 'continuity-check'   // 设定管家核对出处
  | 'assemble-before-write' // 写作官落笔前装配
  | 'gate-review'        // 门禁复核（意图/校对）
  | 'recall-by-need';    // 按需回读早期情节
```
- `AgentMemoryHandle` **没有** `writeGlobal` 方法 —— 想写全局？类型上不存在这个入口。
- `ingest()` 只暴露给编排层（`entity-sink`），角色拿不到。
- **L2-F 与 L2-N 用不同的返回类型**：`FactRef` 与 `Experience`，不能互相赋值（③ 号污染从类型层就断了）。

### 防线③ 运行时守卫（闸门 + 审计）

```ts
export interface MemoryGate {
  /** 放行规则：agentId × keys 白名单 × reason 合法性；任一不满足 → 拒绝并记账 */
  authorize(agentId: string, keys: string[], reason: L1ReadReason): Decision;
}
```
- **reason 必填**：不是形式主义 —— 台账里能回答"它当时为什么读了这条"，复盘才有依据。
- 拒绝也是记录：`memory_audit(agentId, keys, reason, allow, at)`；越权尝试要能在台账里看到。
- 白名单**按角色**给（§5 矩阵），不是"所有角色都能读 L1"。

## 4. 全局记忆的访问：触发条件与边界

**总原则（对应你的要求 3）**：**L1 默认不注入、不缓存、不全局可见**；只有下列四类**具名触发**时才读，
且每次读都带 `reason` 与键白名单，读完**不写回 L2-F 的副本**（只存指针）。

| # | 触发条件 | 谁 | 读什么 | 为什么必须是它来读 |
|---|---|---|---|---|
| 1 | 讨论中要**给出出处**（拦一条设定冲突） | `continuity-keeper` 设定管家 | L1-F：相关实体 + 硬约束 + 伏笔状态 | 它是唯一"必须查库"的角色：拦的每条都要有出处，不能凭印象 |
| 2 | **落笔前装配**（契约已定、开始写） | `writer` 写作官（由编排层代为装配） | L1-F：本章契约涉及的出场角色卡、未回收伏笔、已确立硬设定 | 不注入必然写错，不能交给它自主判断 |
| 3 | **门禁复核**（意图门/校对门） | `reviewer` 意图复核 + 校对 | L1-F：定稿官的契约清单 + 硬设定 | 门的职责就是对照"契约与硬设定"，越权放宽就没门了 |
| 4 | **水车转动**（定稿交付） | 编排层（非角色） | **L1-N 读+写**：舀入新章、最老一斗压梗概 | 这是**唯一**允许写 L1 的时刻与通道 |

**明确禁止（写进代码注释与单测）**
- ❌ 任何角色为"看看别人怎么想的"去读 L1（**reason 里没有这个枚举值**，写不出来）
- ❌ 任何角色读同伴的 L2（防线① 构造不出键 + 防线③ 记违规）
- ❌ 把 L1-N 的原文当事实引用（`FactRef` 类型只接受 `factId`）
- ❌ 把合约/转述/猜测升级成事实（只有 `ingest()` 能写 L1-F，且它只吃**已交付**的沉淀物）
- ❌ 面板/前端直连 L2 表（L2 只经编排层读写，前端要看得走专门的受控接口）

### 4.1 权限矩阵（角色 × 层）

| 智能体 | L2 自己 | L2 同伴 | L1-F 读 | L1-N 读 | L1 写 |
|---|---|---|---|---|---|
| `plot-designer` 剧情设计师 | 读写 | ❌ | brief/genre/角色/大纲/伏笔/约束/前情 | ✅ | ❌ |
| `character-designer` 角色设计师 | 读写 | ❌ | brief/角色/伏笔/约束/前情 | ✅ | ❌ |
| `continuity-keeper` 设定管家 | 读写 | ❌ | **宽**（查库权限，须带出处） | ✅ | ❌ |
| `convener` 定稿官 | 读写 | ❌ | brief/genre/角色/大纲/伏笔/约束/前情 | ✅ | ❌ |
| `writer` 写作官 | 读写 | ❌ | 最宽（含地点/物品） | ✅ | ❌ |
| `reviewer` 意图复核 | 读写 | ❌ | **刻意窄**：brief + 约束 + 伏笔 | ❌（读了正文容易被文笔带偏） | ❌ |
| `proofreader` 校对门 | —— | ❌ | 最宽（含地点/物品/前情） | ✅ | ❌ |
| **编排层 agent** | —— | 可读（受审计） | 全读 | 全读 | **仅 `ingest()` + 水车** |

> ★ 宽度原则（接线时定）：**凡「不注入就会编」的那几类都必须给**（角色卡/伏笔/约束/前情）——
> 这条来自既有教训「让 agent 自己去查防不住幻觉」。**唯一刻意窄的是意图复核**。

> 「白名单」的具体键在 `roles.ts` 里按角色声明（见 §8），**新增角色必须显式声明**，
> 缺省是空集（fail-closed）—— 忘记声明 = 读不到，而不是默认全读。

## 5. 层级一致性：可执行的不变量

| # | 不变量 | 怎么测 |
|---|---|---|
| I1 | `readScope(编排层) ⊇ readScope(任一智能体)` | 属性测试：遍历角色，断言其白名单键集 ⊆ 编排层可读集 |
| I2 | 任何 L2 写入只能落在 `agentId == self` | 用 A 的句柄尝试写 B 的键 → 必须抛/拒绝 |
| I3 | L1-F 的写入途径唯一 | 静态检查：除 `entity-sink` 外无 `ingest` 调用点；运行期断言调用者身份 |
| I4 | 叙事不能冒充事实 | 类型测试：`Experience` 赋给 `FactRef` 编译失败 |
| I5 | 每次 L1 读取都留审计 | 读一次 → `memory_audit` 增一条；含被拒的尝试 |
| I6 | 装配产物可复现 | 同一 `(projectId, chapterNo, agentId, 授权集)` → 同一 digest（便于复现"它当时看到了什么"） |

I6 很值钱：**出问题时能精确重放"这个智能体当时看到了什么"**，否则只能猜。

## 6. 与现有代码的映射（施工清单）

| 设计 | 现有载体 | 改动 |
|---|---|---|
| L1-F 读取器 | `framework/context-resolver.ts`（`resolveSettingsDigest` / `readChapterByOrder`） | 包一层 `MemoryGate`：所有读取走 `queryL1()`，带 reason 与键 |
| L1-F 写入器 | `framework/entity-sink.ts`（交付成功才跑） | 视为 `ingest()` 的实现；补**去重 + 冲突队列**（同槽位两值 → 不覆盖，进 `fact_conflicts`） |
| 水车（迭代器） | ❌ 未实现（架构 §6 只到设计） | 新增 `framework/memory/waterwheel.ts`（纯函数）+ `wheel-store.ts`（**每 agent 一台**，斗位落它自己的 L2）；舀水只在定稿交付/它读到前情时 |
| L2 | ❌ 未实现 | 新增 `framework/agent-memory.ts` + `agent_memory` 表（`agent_id` 必填），一 agent 一命名空间 |
| 角色权限 | `discuss/roles.ts` 的 `DesignRole`（已有 `tools?: string[]`） | **加 `memory?: { readL1?: string[]; l1Wide?: boolean }`**；缺省空集；`continuity-keeper` 给宽 |
| 审计 | 现有治理/台账（`plugin_kv`） | 新增 `memory_audit` 表（读/拒/写三类事件） |
| 现役的"上一章全文注入" | `resolvePreviousChapter`（`PREV_CHAPTER_MAX_CHARS = 6000`） | 语义不变，但登记为**水车第 1 斗**，为扩到 3 斗留位（体量代价另议） |

**注意**：`entity-sink` 现在是"交付成功后落库"的**唯一**写通道 —— 这个性质要保住，
它是本架构"不污染"的地基：**草稿永远进不了 L1**。

## 7. 防污染验收清单

| # | 验收点 | 断言 |
|---|---|---|
| 1 | 跨智能体读私记 | A 的句柄读 B 的键 → 拒绝 + 审计留违规记录 |
| 2 | 写全局 | 角色句柄上不存在 `ingest`；伪造调用 → 运行期拒绝 |
| 3 | 叙事冒充事实 | 把 L1-N 原文塞进 `FactRef` → 类型/运行期双层拒绝 |
| 4 | 草稿污染 | 交付前调用 `ingest` → 拒绝（只吃已交付物） |
| 5 | 未授权读 L1 | 不声明白名单的角色读 L1-F → 空结果 + 审计 |
| 6 | 事实冲突 | 同一槽位两次不同值 → 不覆盖，进 `fact_conflicts` 待人工/定稿官裁 |
| 7 | 装配可复现 | 同输入 → 同 digest（I6） |
| 8 | 角色新增 | 忘记声明 `memory` → 读 L1 得空集（fail-closed），不是全读 |

## 8. 分期

### 8.2 实现中发现并修正的两处设计缺陷（值得记）

1. **闸门需要两种判定语义，不能只有一种**：
   - `strict`（默认）：**一个键越界就整次拒绝** —— 用于"查一条具体事实"（越界＝调用方搞错了角色）
   - `partial`：**按白名单部分放行** —— 用于"装配一整个 digest"（包给多个字段，角色拿获准的那部分）
   最初只写了 strict，结果窄白名单角色装配时整包被拒、digest 全空 —— 实测暴露。

2. **白名单的「族名」必须覆盖子树**：
   `settings.brief` 这种不带通配的写法，要能命中 `settings.brief` 和 `settings.brief.x`。
   只做精确匹配的话，声明侧写族名、申请侧拼带尾巴的键 —— "看着声明了却读不到"，
   而且**不报错**（静默少给），属于最难查的一类问题。

3. **「请求叙事式被拒」不能株连事实式**：
   叙事闸门原本是个"前置一票否决"，结果 `reviewer`（readNarrative=false）在装配整包时
   **连它获准的契约字段一起拿不到**（实测：digest 全空）。改成 partial 模式下叙事被拒
   只体现为"不注入上一章"，事实部分照常按白名单给。

4. **白名单的宽度原则（接线时才想清）**：最初按"最小可见"给角色配白名单，
   但既有注释写着一条血泪教训 ——「让 agent 自己去查**防不住幻觉**，事实必须由框架直接提供」。
   两者冲突。定了口径：**凡「不注入就会编」的那几类（角色卡 / 伏笔 / 约束 / 前情）都必须给**，
   差异只保留在「要不要地点/物品」这一档；**全表唯一刻意窄的是意图复核**（它只对契约，
   读了正文反而被文笔带偏）。

### 8.5 「写入 → 随机抽查 → 完善」循环（2026-09-13）

抽查脚本：`scripts/memory-sample-check.mjs`
（抽样给人看 + **不变量自动判定**，退出码可直接进 CI；用法 `node scripts/memory-sample-check.mjs [projectId] [抽样数]`）

**怎么用**：先真跑几章把记忆写进去（`scripts/run-chapters.mjs --new --from 1 --count 4`），再抽查。
抽查的不变量：agent_id 非空 / 枚举合法 / keys 是 JSON 数组 /
**水车章号严格降序无重复且不超容量** / 斗位正文非空 / **出界记录不能同时还在斗位里** /
agent_id 不含斜杠（防拼接式越权）。

#### 首次抽查就抓到两个真缺陷（都被修掉并复验）

| # | 现象（抽查发现） | 根因 | 修复 | 复验 |
|---|---|---|---|---|
| 1 | **4 章只留下 13 条经历**（本该 ~40 条） | L2 经历的 key 用了 `turn.9` 这种**每章都会重算的编号** → 后章把前章**覆盖**掉了 | key 改 `exp.ch<N>.turn<M>`（流水线侧同理加阶段名） | 写第 5 章后 L2 18 → 30 条，不再互相覆盖 |
| 2 | **`wheel.summary.*` 一条都没有**（出界机制等于死代码） | 注入策略每次都把"最近 N 章"**重播**一遍 → 斗位刚好填满，**永不发生出界** | 改成**空斗才播种**（最近 N 章垫底保连续性），之后**只舀新章** | 水车 `[ch3,ch2,ch1]` → `[ch4,ch3,ch2]`，并首次出现 `wheel.summary.1`（85 字，压在 writer 自己的长期池） |

> 教训：**"机制写了" ≠ "机制在跑"**。第 2 条尤其典型 —— 单测里 `pushChapter` 的轮转/出界全绿，
> 但真实路径上永远喂不满，于是那句"出界压成一句话"从未执行过。**只有真跑 + 抽查数据才能发现**。
> 第 1 条同理：覆盖是"静默成功"（upsert 不报错），不数条数根本看不出来。

#### 顺带接上的两处（此前只在单测里存在）

- **沉淀侧的批次矛盾拦截**：`entity-sink` 在落库前跑 `screenBatchConflicts` ——
  同一章里同一槽位两个不同值 = 模型自相矛盾 → **两条都不落库** + 进 `fact_conflicts`。
  抽查里已经抓到真例子（`characters/陈默/state`）。
- **出界压缩**：`compressEvicted` 调一次模型把出界章压成一句话（**按章号缓存**，同一章只调一次，
  省掉 5 个角色各压一遍）。

### 8.6 第二轮「写入 → 抽查 → 完善」（2026-09-13 晚）

#### 修：模型输出取 JSON 不再脆断（通用工具层）

抽查前先修了上一轮发现的**校对门 JSON 解析失败即放行**：

| 层 | 改动 |
|---|---|
| `helpers.parseJsonLoose` | **根因**：原实现取「第一个 `{` 到最后一个 `}`」→ 模型输出**两个 JSON** 时切片跨过两个对象，直接报 `Unexpected non-whitespace character after JSON`。新增 `extractFirstJson()`：**括号配平扫描**（跳过字符串内括号与转义） |
| `gates` 两门（校对 / 润色） | 新增 `completeJson()`：**解析失败自动重试一次**（第二次附更硬的格式要求）。解析失败 = 这一步没执行，重试成本远低于漏检 |

**真机效果**（5 章连写）：`[gates] 校对官第 1 次输出无法解析，重试一次` ×1 →
`校对官第二次输出才解析成功` ×1 → **`校对门未能执行` 0 次**（上一轮 3 章里失败 2 次）。
即：这 5 章的校对门**全部真正执行了**。

#### 补：两处"只在单测里存在"的接线

- **沉淀侧批次矛盾拦截**已接（`entity-sink` → `screenBatchConflicts`）：本轮 5 章抓到 **2 条真冲突**
  （`characters/陈默/state`、`characters/老周/state` 各自在 ch4 同批次里给了两个值）。
- **出界压缩**已生效：抽查到 `wheel.summary.1`（103 字）。

#### 再补：「水车斗位」上界面 + 抽查进 CI

- `/memory` 接口的 `agents[]` 增加 `wheel: number[]`（斗 1 最新）与 `summaries: number[]`；
  面板按角色显示 `水车 ch4 ch3 ch2`（斗 1 高亮）+ `已归档 ch1`。
  ★ 副产物：**意图复核的水车是空的** —— 因为它 `readNarrative=false`，读不到章节正文，
  这是权限矩阵在数据上的可见证据。
- `package.json` 加 `verify:memory` → `node scripts/memory-sample-check.mjs`（抽查 + 不变量，退出码可进 CI）。

#### 抽查又抓到第 3 个缺陷：时间戳「秒/毫秒」搞混

抽样里所有审计时间都显示 `01:01:30` —— 一查：drizzle 的 `timestamp` 列存的是**秒**
（`at = 1789290856`），而抽查脚本与 `/memory` 路由都当**毫秒**用 → 全渲染成 1970 年。
两处已修，并**新增不变量 I8**（时间戳必须落在 2020 年至今 +1 天内）——
这类"单位搞混"以后能**自动被抓**，不靠人眼。

## 9. 与《ai-writing-architecture.md §6 水车》的关系

不是两套设计，是**职责分工**关系（2026-09-13 按作者澄清修正）：

- §6 的水车 = 本文**「记忆的迭代方式」** —— 固定斗数、舀/倒/压梗概、三层时间戳，
  **实现在每个智能体自己的 L2 里**（`wheel-store.ts`，斗位存 `agent_memory` 的 `wheel.slots`）。
  ⚠️ **不是** L1 的共享记忆层（早先版本写错了，已改）。
- §7 的「常驻 / 强制注入 / 按需读取」= 本文 **§4 的四类具名触发**（把"按需读取"明确成带 reason 的授权查询）；
  其中**常驻的那一份就是该智能体水车里的斗位**（不是全项目共享的一份）。
- §6 里「上一章全文」这种素材：**不属 L1**，它是被读取的项目数据；读到后进**读者自己的**水车。

|---|---|
