先对一下你的理解

你的写法实际差在哪
总 > 两个大模块 总 = 1 个宿主（Electron 壳 + Web 界面 + 本地服务端 + 共享库），上面挂两组插件：manual 组、auto 组 不是两套独立程序。两组插件共用同一个界面壳、同一套插件注册表、同一个后端、同一个 SQLite；切模式 = 换哪组插件生效。

AI 写作 > 还未实现 ⚠ 改成「写过，2026-10-01 实现被剥离出仓，仓内刻意只留骨架」 所以现象不是「没这个模块」，而是「入口还在、点开是未安装 / 接口 404」。107 个实现文件 + SHA256 清单暂存在仓外。

① 运行时：从上到下 5 层

① 桌面端 · apps/desktop 在场
Electron 外壳。只做三件事：把前端产物 web-dist 和 5 个内置插件 seed-plugins 拷进安装包 → 拉起本地服务端进程 → 开窗口访问它。
↓
② 前端壳 + 插件内核 · apps/web 在场
React 应用。项目布局 ProjectLayout、停靠系统 DockShell、插件注册表与扩展点（projectPanels / builtinPanels / chatRail / workbench / settings / capability）、手写/自动模式切换都在这层。插件靠 import.meta.glob 在构建期收集。
↓
③ 共享库 · packages/* + apps/plugins/shared/* 在场
packages/ 下只有 core（插件系统 + manifest 校验）、db、shared 三个包；ui-kit、ui-graph、data-core 实际在 apps/plugins/shared/（包名 @novel-plugins/ui-kit、@novel-plugins/ui-graph、@novel-plugins/data-core）。两组插件都依赖它们。
↓
④ 本地服务端 · apps/server（Hono） 在场
启动时扫一次插件目录 → 挂载各插件路由 → SQLite 双库 → AI 代理（modules/ai.ts，全部 AI 端点都在这）。
↓
⑤ 数据与旁路 可选
SQLite 双库（全局 / 项目）；另有 Python 旁路 apps/agents（可独立跑，不在主流程上）。

③ 手写模式里的 AI 到底能用到什么程度

这是两组插件交叉的地方：手写台的面板全在，但它们要的「AI 能力」的提供方大多在 AI 写作那半。

能力 / 接口现状点下去会发生什么
A · 真的能发出去（会真的请求大模型）
POST /ai/chat-stream可用右栏「AI 对话」面板 + 拆书对话，流式返回。
POST /ai/generate-character可用角色页的「AI 生成」。这是手写台唯一会显式报错的 AI 能力，其他都是静默。
POST /ai/analyze-style可用文风顾问；失败时静默回落，不提示。
B · 想发但发不出去（能力键在手写台，提供方随 AI 写作出仓）
ai.scan 实体扫描断链后台自动实体扫描。useAutoEntityDetection 开头就 if (!scan) return; —— 整个扫描逻辑静默不执行，不报错也没有 UI 提示。
ai.quickPhrases 快捷短语降级回落成本地启发式规则 quickPhraseHeuristic.ts，看起来还在工作，其实没有 AI。
ai.timelineExtract 时间线抽取死按钮按钮无条件渲染、可点，但能力读取失败后直接 return：点下去毫无反应（注释写的却是「入口隐藏」，与实现不符）。
ai.outlineFill 大纲补全无消费点能力键在，手写台没有任何地方调用它。
ai.entityRefresh 实体刷新无提供方同上。
C · 缺的是界面（服务端有端点，手写台没有入口）
技能库 / 技能市场 / 13 个工具缺 UI端点已实现（含 /ai/skill-library*），但手写台没有任何技能库 / 技能市场入口；worldbuilding 插件注册的势力顾问技能也因此失去触发路径（技能面板 UI 随 AI 写作台出仓）。
「AI 设置」栏目空栏目设置页留了 category=ai 这一栏，但全仓没有任何插件注册它 ⇒ 打开就是空的。
红石开关面板出仓手写台提示语指向这个面板，但面板本身在 AI 写作台里。
D · 一个已经死了的事件
顶栏「重写」死事件已核实：ProjectLayout 只负责派发 new CustomEvent('nm:rewrite')，全仓没有任何监听者。它属于 AI 重写链路（同一批随 auto 工作台出仓），此因果为推断。

④ 所以现在的架构一句话总结

宿主（Electron 壳 + Web 界面 + 插件内核 + 本地服务端 + 共享库）
  ├ 手写模式插件组：手写台（12 面板 + 章节左栏 + 编辑器）、拆书、世界观建造师、排印 —— 这批是完整的
  └ 自动模式插件组：AI 写作台（1 个槽）、自动写作引擎（no-op 骨架）—— 实现 107 文件暂存仓外

手写模式自身能跑通（写章节、管角色、管时间线、AI 对话都能用），但凡是「要点自动 / 要点红石」的功能都是断的，因为那半边的提供方被搬出了仓库。
想恢复 AI 写作：把 F:\new1.2-detached\ai-autowrite-module 下的 workbench 与 novel.autowrite 拷回 apps/plugins/auto/，然后重启 vite dev（import.meta.glob 是构建期展开）并重启服务端（插件目录只在启动时扫一次），不需要 pnpm install。
