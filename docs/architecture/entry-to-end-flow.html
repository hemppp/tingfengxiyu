关于这张图

同 Nx Project Graph 的渲染方式（节点方块 + 带类型的边 + 点选看详情），但语义换成一条自上而下的执行流程：从双击图标开始，到内容落库、界面回填结束。

纵向 12 行 = 12 个阶段；行内横向偏移 = 主干（中间）与旁支（两侧）。流程顺序看方块左上角的步骤号，与底部清单表一一对应。

边（关系）图例

启动 / 进程 boot
鉴权 / 门禁 / 校验 gate
调用 / 挂载 call
流 / 供应商往返 stream
落库 / 持久化 data
分支 / 旁路 branch
断链 / 死路 dead
回环 / 下次启动 loop

怎么读

  • 鼠标移到线上看依据；点方块看角色、证据、备注。
  • 勾掉某类边可只看一种关系；只看主干 会隐藏所有旁支与断链。
  • 顶部模式按钮：手写台 只留手写侧与共享面；自动台 在本流程里只有共享/宿主面 —— 自动写作模块 Web 面已出仓，无独立链路可画。
  • 快捷键：f 适配 · m 只看主干 · 1/2/3 模式 · Esc 取消选择。

口径

每条边与每个方块的依据都是 文件:行号，取自仓内现状（读源码核对，无 shell 无法跑构建）。断链（红虚线）不代表「线不存在」，而是仓内没有另一端：能力无提供方、路由无调用点、事件无监听者。

—

实线 = 真实存在的数据/控制流；虚线 = 分支（灰）· 断链（红）· 回环（蓝紫）。红虚线终点那些方块，就是「图上画得出来、程序里走不到」的部分。
