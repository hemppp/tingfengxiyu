# VSCode 式分页工作区 + 气泡看板 · 设计

> 需求原文要点：①各功能面板以**分页（Tab）**方式打开、切换、关闭，支持多标签并行；
> ②功能看板做成**圆形气泡**，放在 **AI 交流区旁边**、**竖直漂浮排列**，点击后以**类似 VSCode 打开分页**的方式展示，
> 用于查看**当前实时运转的数据**；③**书写正文区域始终保持打开**，不随分页切换或数据查看而被关闭或替换。
>
> 本文是**交互与结构规格**（可直接施工）。落笔 2026-09-13。

---

## 0. 先说清一个绕不过去的取舍（它决定整个结构）

**「正文始终打开」和「分页切换」不可能落在同一块区域里** —— 同一区域切换标签，必然有一次内容被替换。
所以两者只能这样同时成立：

| 方案 | 做法 | 结论 |
|---|---|---|
| **A（推荐）正文 = 固定主视图** | 正文占一块**永不参与分页**的区域；标签页属于它**旁边**的「辅助分页区」 | ✅ 每个字面要求都成立：正文不被关闭、不被替换；标签仍可开多个、并行切换 |
| B 正文 = 不可关闭的 pinned 标签 | 正文和其它面板在同一个标签区里切换，只是关不掉 | ❌ 切到别的标签时正文**就是被替换了**，违背需求第二句 |

**方案 A 的补强**：正文在标签栏里也渲染一个**带图钉、无关闭按钮的固定项**（视觉上是标签）。
点它 = 收起辅助分页区、把焦点还给正文。这样"正文始终打开"在 UI 上也是字面成立的，
而它本质上是个「回到正文」的按钮，不参与标签轮换。

> 若你更想要 B 那种"纯 VSCode 感"，只需改一处：把正文当作 pinned tab 放进同一个标签条
> —— 但请接受"切走时正文不在画面上"。其余规格（气泡、标签行为、快捷键、持久化）完全不变。

## 1. 现状盘点（改什么、留什么）

目前项目里有**三套并存**的面板入口，这次要收敛成一套：

| 现在 | 在哪 | 这次怎么变 |
|---|---|---|
| 转轮气泡（罗盘 + 半圆扇，悬停开花） | `components/layout/FloatingBubbles.tsx` | → **竖直气泡列** `BubbleRail`（罗盘保留为「全部面板」选择器入口） |

| AI 模式写死三栏（交流流 / 正文+仪表盘 / 实体栏） | `components/layout/AutoWriteWorkbench.tsx` | → **正文主视图 + 辅助分页区**；`WorldStateBoard` / `EntityRail` 变成可开的面板 |


### 2.1 尺寸与档位

| 元素 | 规格 |
|---|---|
| 气泡 | 直径 **30**，中心间距 **38**（净空 8），列宽 **44** —— 2026-09-13 作者要求"小一点"，从 40/56 缩下来 |
| 气泡列 | 贴 AI 栏右缘 **12**，**垂直居中**，上下各留 24 安全区；数量超出时**列内滚动**（不换行、不缩小） |
| 正文主视图 | 最小宽 **480**；正文排版沿用现有宣纸/衬线规范 |
| 分页区 | 默认 **420**，可拖 **320–720**；可整栏收起（记住上次宽度） |
| 标签 | 高 **28**，最大宽 **176**（超出省略），标签栏高 **36** |
| 拖动分隔条 | 5px（与现有双分隔条一致的手感） |

### 2.2 窄屏：**让位阶梯**（2026-09-13 定稿：正文不能被挡住）

原方案里的「覆盖层 / 抽屉」**已废弃** —— 作者明确要求**正文不能被挡住**。改成逐级让位，
任何一级都不覆盖正文。**2026-09-13 二轮补充**：作者又要求「点击气泡是在**正文旁边**打开页面，不是在角落」——
所以第 ③ 级改成**先压窄侧组**，把"落到下方"降为最后手段：

| 级 | 触发条件 | 做法 | 正文状态 |
|---|---|---|---|
| ① | 放得下 | AI 栏 + 气泡列 + 正文 + 右栏侧组**并排**（用作者设的宽度） | 完整可见 |
| ② | `视口 − 气泡列 − AI 栏 − 侧组 < 正文预算` | **自动收起 AI 交流栏**（空间回来后自动恢复；**不改写作者的收起偏好**） | 完整可见 |
| ③ | 收掉 AI 栏仍不够 | **把侧组压窄**（420 → 最低 `PANE_W_MIN_SOFT`＝280），**保住"在正文旁边"** | 完整可见 |
| ④ | 压到最窄仍不够（视口 ≲ 756） | 才把侧组挪到正文**下方**（高 200–560，可拖） | 宽度完整、只是变矮 |
| ⑤ | 窗口极矮 | 下方侧组高度自动压回（至少给正文留 320px 高） | 仍完整 |

★ 一句话：**允许变窄，不允许遮挡，也不轻易甩到角落**。所以布局里不存在 `position: absolute` 的侧组容器。

## 3. 分页交互规范

### 3.1 状态模型

```ts
// stores/workspaceStore.ts（新）
interface WorkspaceState {
  tabs: string[];              // 面板 key，按标签顺序（不含正文）
  active: string | null;       // 当前激活的面板；null = 正文在前台（分页区可收起）
  paneOpen: boolean;           // 分页区展开/收起
  paneWidth: number;           // 记忆宽度（320–720）
  pinned: string[];            // 固定在最左的标签（可选，P2）
  mru: string[];               // 最近使用顺序（Ctrl+Tab 用）
  unread: Record<string, boolean>; // 面板在后台有更新 → 标签上一颗小点（可选，P2）
  // 动作
  openPanel(key): void;        // 不存在则追加+激活；存在则激活（幂等）
  closePanel(key): void;       // 关掉；若关的是最后一个 → paneOpen=false
  activate(key | null): void;  // null = 回到正文（收起分页区）
  toggleBubble(key): void;     // 气泡三态行为（见 §4.2）
  setWidth(w): void; setPaneOpen(b): void; moveTab(from, to): void;
}
```

**为什么新起一个 store 而不是扩 `panelOpenStore`**：现有那个只有 `keys[]`（谁开着）而没有"顺序/激活/最近使用/分页区展开态"，
而标签语义里**顺序与激活是核心**。新增 store 后把老的 `keys/open/toggle/close` 映射过去（`openPanel` 幂等），旧调用点可渐进迁移。

### 3.2 标签行为总表

| 动作 | 结果 |
|---|---|
| 单击标签 | 激活；更新 MRU |
| 中键 / `Ctrl+W`（焦点在分页区） | 关闭该标签 |
| 关闭**当前**标签 | 激活**右邻**；无右邻取**左邻**；都没有 → `paneOpen=false`（**正文占满**） |
| 关闭**非当前**标签 | 当前激活不变 |
| 关闭最后一个标签 | 分页区收起，**不销毁**正文、不改变正文状态 |
| 拖动标签 | 同区内重排（`moveTab`），顺序持久化 |
| 双击标签 | 固定 / 取消固定（固定的排最左，× 变成图钉，右键才能关）〔P2〕 |
| 右键标签 | 菜单：关闭 / 关闭其他 / 关闭右侧 / 固定 / — / 复制面板 key〔P2〕 |
| 标签溢出标签栏 | 标签栏**横向滚动** + 末端「已打开 N」下拉（列出全部，点击切换） |
| 同一面板再开 | **不新建第二个标签**（面板单例）。要并排看两份，用两个浏览器标签页 —— V1 明确不支持 |
| 重复点气泡 | 见 §4.2 —— 气泡是「显示/隐藏」开关，**永不销毁**面板 |

★ **不设打开数量硬上限**（现状 `MAX_OPEN_PANELS` 会静默挤掉最早的标签，那是"做了但用户不知道"的错）：
改为溢出滚动 + 下拉列表，让作者自己控制。

### 3.3 键盘（只在分页区获得焦点时拦截，避免抢浏览器快捷键）

| 键 | 行为 |
|---|---|
| `Ctrl/⌘ + W` | 关闭当前标签（**焦点在正文编辑器内时不拦截** —— 否则会和浏览器"关闭标签页"打架） |
| `Ctrl + Tab` / `Ctrl + Shift + Tab` | 按 MRU 上一个/下一个 |
| `Ctrl + 1…9` | 跳到第 N 个标签（`1` = 回到正文） |
| `Ctrl + B` | 收起/展开分页区 |
| `Esc` | 分页区收起（焦点不在正文时） |
| `Ctrl + K` | 复用现有命令面板，新增「打开面板：X」条目 |

### 3.4 无障碍与可测属性

- 标签栏 `role="tablist"`，标签 `role="tab" aria-selected`，内容区 `role="tabpanel"`；←/→ 切换、Home/End 到首/尾。
- 每个标签带 `data-panel-key`，正文固定项带 `data-panel-key="__body__"` —— 自动化测试靠它定位。
- 气泡：`role="button"` + `aria-pressed`（打开态）+ `aria-label="打开角色面板（已打开，点击收起）"`。

## 4. 气泡看板规范

### 4.1 布局

- **位置**：紧贴 AI 交流区**右缘**（2026-09-13 定稿；中途试过挪到最左当活动栏，被作者否掉并要求放回 AI 右侧）；**垂直居中**于工作区高度。
- **排列**：**竖直一列**，自上而下；中心间距 38（直径 30 + 净空 8）。
- **两段分组**（用一条 8px 的细分隔线隔开，不折叠）：
  - 上段「**写作中**」：流水线、本章计划、世界状态、一致性、字数统计
  - 下段「**资料**」：角色、地点、物品、伏笔、大纲、时间线、笔记、地图、关系图、参考书、导出
- **数量超出**（列高不够）：列内**纵向滚动**，滚动条极细；列顶部/底部出现渐隐遮罩提示还有更多。
- **漂浮感**：气泡带 1px 高光边 + 极轻阴影（沿用现有气泡的 `radial-gradient` + `backdrop-blur` 风格），
  **不随页面滚动消失**（它是工作区固定层，不是内容层）。
- **不使用**现有的「悬停开花 + 半圆扇」：扇形的半径随数量膨胀、还会被视口边缘钳制，竖向排列对 20+ 个面板更稳。

### 4.2 点击行为（三态，**这是最容易做歪的地方**）

| 状态 | 气泡 | 分页区 | 点击结果 |
|---|---|---|---|
| 1 | 无标签 | 任意 | **新建标签**（追加到末尾）→ 激活 → 展开分页区 → 气泡高亮 |
| 2 | 有标签，但不是当前 | 任意 | **切到它**（分页区若收起则先展开）→ 把它滚到可见 → 旧标签失焦 |
| 3 | 有标签，且是当前 | 展开 | **收起分页区**（标签保留、**不关闭**）→ 气泡取消高亮 → 再点一次恢复 |
| 3' | 有标签，且是当前 | 收起 | **展开并激活**（回到状态 3 的前一步） |

**一句话记住**：**气泡 = 显示/隐藏开关；关闭只能走标签上的 `×` / 中键 / `Ctrl+W`。**
这样作者在"看一眼数据就回来写"的循环里，永远不会因为点气泡而丢掉面板里的状态（表单、滚动位置、筛选条件）。

气泡的右键菜单（〔P2〕）：打开 / 收起 / 关闭该面板 / 关闭其他面板 / 固定到标签栏最左。

### 4.3 三种视觉状态

| 状态 | 表现 |
|---|---|
| 待机 | 半透明玻璃底 + 图标（`hsl(var(--ink) / 0.7)`） |
| **运转中**（`running`） | 外圈**呼吸环**（1.8s，`prefers-reduced-motion` 时改为静止实心点）+ 右上角脉冲点 |
| 已打开 | 主题色底 + 白色图标；对应标签同时高亮 |
| 有实时数值 | 右下角**徽标**：数字 ≤99 显示数值，>99 显示 `99+`；非数字用一颗小点表示"有新内容" |

### 4.4 实时数据从哪来（别让 12 个气泡各自轮询）

统一一个订阅源：

```ts
// hooks/usePanelSignals.ts（新）
// 一处订阅 → 产出所有面板的徽标/运转态，气泡列与标签栏共用
export function usePanelSignals(): Record<string, { badge?: number | true; running?: boolean }>
```

| 面板 | 徽标（实时） | 运转中 |
|---|---|---|
| 流水线 | 已定稿段数 `n/7` | 有阶段 running 时 |
| 角色 / 地点 / 物品 / 伏笔 | 条目数；伏笔用「未回收数」 | — |
| 本章计划 / 世界状态 | — | 会话进行中 |
| 统计 | 今日字数增量 | — |
| 一致性 | 未处理冲突数 | 校对进行中 |
| 笔记 / 大纲 / 时间线 | 条目数 | — |

面板**内部**的实时刷新沿用各自既有的 store 订阅，不为标签化重写数据层（避免把稳定路径改坏）。

- 面板组件一律包 `PanelGuard`（已有错误边界）：**面板崩了只显示占位，不许把正文带走**。

## 6. 正文常驻：工程硬约束与验收

**硬约束（必须可测，不能只是"我们注意了"）**

1. 正文组件在**整个工作区生命周期内只挂载一次**；切标签、开关分页区、切档位（并排→覆盖→抽屉）都**不触发卸载**。
2. 切换前后必须保持不变：编辑器 DOM 节点引用、`contenteditable` 的**光标 offset**、`scrollTop`、当前章节 id。
3. 面板异常/崩溃**不得**影响正文（错误边界隔离在面板内）。
4. 让位阶梯的**每一级都不覆盖正文**（见 §2.2）：分页面板不得使用 `position: absolute` 之类脱离文档流的定位。

**验收清单（可自动化的写在括号里）**

| # | 验收点 | 断言 |
|---|---|---|
| 1 | 点气泡开面板 | `[data-panel-key="characters"]` 出现并 `aria-selected=true`；正文容器 `data-body-mounted` 上的**挂载次数计数器仍为 1** |
| 2 | 连开 5 个面板 | 5 个标签并存、可来回切；正文挂载计数仍 1、光标 offset 不变 |
| 3 | 点**当前**气泡 | 分页区收起、标签仍在（`tabs.length` 不变）；正文占满；再点恢复 |
| 4 | 关闭当前标签 | 激活右邻；无右邻取左邻；全部关掉 → 分页区收起 |

## 10. IDE 化改造（2026-09-13 二轮，用户要求"跟 IDE 一致"）

第一轮做成了"右侧面板 + 标签"，那**不是 IDE**。IDE 的关键是：**标签属于「编辑器组」**，
文件在编辑器里打开、切换发生在组内，而且可以**并列多个编辑器组**。这一轮按这个语义重构：

### 10.1 布局（对齐 VSCode 的分区）

```
┌───────────────────────────────────────────────────────────────────────┐
│ 标题栏：← 书名 · [AI 写作] · 折叠侧栏 / 折叠组 2                        │
├────────────┬──────┬─────────────────────────┬─────────────────────────┤
│ 侧栏        │气泡列 │ 编辑器组 1（主）          │ 编辑器组 2（侧）          │
│ AI 交流     │(功能 │ ┌ 📌正文 ─────────────┐ │ ┌ 流水线 × │ 本章计划 × ┐│
│            │ 看板)│ ├─────────────────────┤ │ ├───────────────────────┤│
│            │      │ │ 第 N 章（面包屑行）   │ │ │                       ││
│            │      │ │ 正文内容（常驻）      │ │ │ 看板内容               ││
│            │      │ └─────────────────────┘ │ └───────────────────────┘│
├────────────┴──────┴─────────────────────────┴─────────────────────────┤
│ 状态栏：花名册 · 流水线 n/7 · 库中 N 章 · 组 2: 当前看板 · 快捷键提示       │
└───────────────────────────────────────────────────────────────────────┘
```

- **气泡列紧贴 AI 对话区右边**（2026-09-13 定）。⚠️ 中途试过把它挪到最左当 VSCode 的"活动栏"，
  **被作者否掉并要求放回 AI 右侧** —— 别改回去。
- **组 1（主编辑器）只有一条不可关闭的固定标签「正文」** —— 它就是"编辑器里打开的那份稿子"。
- **组 2（侧编辑器）** 才是看板标签，可开可关；宽度不够时按 §2.2 让位（**仍然绝不覆盖正文**）。
- AI 栏与（气泡列 + 编辑器区）之间是可拖的分隔条，向右拖 = 对话栏变宽。

### 10.5 标签栏的视觉规范（2026-09-13 三轮：作者贴了 VSCode 截图说"类似这样"）

作者要的是 VSCode 标签**长什么样**，不是功能。照做：

| 项 | 规范 | 为什么 |
|---|---|---|
| 标签栏底色 | `hsl(var(--secondary) / 0.55)` 一条浅色条 + 底边 0.5px | VSCode 的 tab strip 比编辑器暗 |
| **激活标签底色** | **`EDITOR_BG`（与下方编辑器内容同一个值）** —— "连成一片" | VSCode 的关键观感：激活标签看起来是内容的一部分 |
| **激活指示** | **顶部 1px 强调线**（`inset 0 1px 0 primary`） | ★ 之前用的是**底部下划线**，那是浏览器标签的画法，VSCode 是顶部 |
| **关闭按钮 ×** | **只在激活或悬停时出现**（未激活时 `opacity: 0`，hover 才显形） | ★ 之前每个标签都常显 ×，整排很吵；VSCode 只在当前标签上常显 |
| 高度 | 35 | VSCode 约 35px |
| 标签尺寸 | `minWidth 110 / maxWidth 200`，`padding 0 8px 0 10px` | VSCode：最小约 120、最大约 240 |
| 图标 + 文字 | 前图标（12–13px）+ 名称（12.5px），`truncate` | 与 VSCode 的"文件类型图标 + 文件名"同构 |
| 预览标签 | 名称**斜体** | VSCode 的预览标签就是斜体 |
| 固定标签 | 名称前一个**图钉**图标（VSCode 的 pinned tab 也是图钉） | 「正文」用它表示不可关闭 |

★ `EDITOR_BG` 抽在 `workspaceDefs.ts` 里是**单一来源**：标签栏、组 1、组 2 三处必须同值，
  否则"连成一片"就断了（当天已经被同类问题咬过一次：正文最小宽预算两处各写一个数）。

### 10.2 打开文件的方式（对齐 IDE）
| 操作 | IDE 里的对应 | 行为 |
|---|---|---|
| **单击气泡** | 资源管理器单击文件 | **预览打开**：标签标题**斜体**、气泡虚线描边；预览只有**一个槽位**，再预览别的会**顶掉**它 |
| **双击气泡** | 双击文件 | **固定打开**：预览晋级为正式标签 |
| **右键标签** | 右键编辑器标签 | 关闭 / 关闭其他 / 关闭右侧 / 固定 |
| **Ctrl+P** | Quick Open | 面板搜索框：输入筛选、↑↓选择、Enter **固定打开** |
| 中键 / `×` / `Ctrl+W` | 同 IDE | 关闭该标签（关当前 → 激活右邻，其次左邻） |
| `Ctrl+\` | 分栏 | 展开 / 收起组 2 |
| `Ctrl+B` | 侧栏 | 收起 / 展开侧编辑器组 |
| `Ctrl+1…9` | 跳标签 | `1` = 回正文，`2…` = 组 2 的第 N 个标签 |
| 溢出 | 「已打开的编辑器」 | 标签栏横向滚动 + 右端下拉列出全部 + 「显示全部看板…」 |

★ **预览标签不持久化**：刷新后预览槽是空的（IDE 重启也是这样），固定标签原样恢复。
